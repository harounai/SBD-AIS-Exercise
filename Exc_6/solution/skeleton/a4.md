# Adding MinIO and Updating Docker Compose

The main task of this exercise was to integrate **MinIO** as an S3-compatible storage service. I added a new `order-minio` service to the docker-compose file, set the right credentials, exposed the ports, and added a persistent volume for the data.

Later, I updated the MinIO command so it starts both the S3 API and the console correctly:

```yaml
command: ["server", "--address", ":9000", "--console-address", ":8500", "/data"]
```

This way the API runs on port 9000 and the dashboard on 8500.

I also updated the orderservice environment variable:

```yaml
S3_ENDPOINT=order-minio:9000
```

so the service connects to the correct API port.

# Uploading + Downloading Receipts via S3

In `rest/api.go`, I completed the two required endpoints:

### POST /api/order

* Save the order in the database
* Convert it to markdown
* Upload the file to MinIO using `PutObject`

### GET /api/receipt/{id}

* Fetch the order from the database
* Load the matching receipt from MinIO using `GetObject`
* Send it back as a downloadable file with the correct headers

This connects everything: database → receipt → MinIO → browser.

# Handling Some Setup Issues

During the process I ran into a few problems with ports, networks, and overall environment setup. Things like S3 timeouts, Traefik routing not responding, and old Docker data interfering with new builds.

To clean everything up, I reset my Docker environment by removing unused containers, volumes, and images:

```bash
docker compose down
docker ps -aq | xargs docker rm -f
docker images -q | xargs docker rmi -f
docker volume prune -f
docker network prune -f
```

I also double-checked `/etc/hosts`, fixed a few missing network connections in compose, adjusted Traefik’s config, and rebuilt everything:

```bash
docker compose up --build -d
```

After that, all services communicated properly and the environment ran smoothly.
