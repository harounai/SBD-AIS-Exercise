### Errors/Summary:

1. Checked the container logs to find out what went wrong:

   ```bash
   docker logs pgdb_sbd
   docker logs skeleton-ordersystem-1
   ```

   PostgreSQL showed an error related to version 18 and the data directory path, and the app failed to connect because the database never started.

2. Adjusted the issue by updating the volume path in the `docker-compose.yml` file.
   Changed this:

   ```yaml
   - pgdata_sbd:/var/lib/postgresql/data
   ```

   to this:

   ```yaml
   - pgdata_sbd:/var/lib/postgresql
   ```

3. Cleaned everything up and restarted:

   ```bash
   docker compose down
   docker volume rm skeleton_pgdata_sbd
   docker compose up -d
   ```

   After that, both containers started correctly and stayed “Up.”

4. Verified with:

   ```bash
   docker ps
   ```

   PostgreSQL (`pgdb_sbd`) was up and running on port `5432`.

5. When the app container wasn’t visible at first, I brought it up manually:

   ```bash
   docker compose up -d ordersystem
   ```

   Then checked again and both containers were running fine together.

6. Opened the app in my browser at [http://localhost:3000](http://localhost:3000) — the service loaded successfully, confirming it was connected to the database.
